# Security Policy

## Reporting a vulnerability

Please report security issues privately through
[GitHub Security Advisories](https://github.com/prompton-dev/prompton/security/advisories/new)
rather than opening a public issue.

Include what you can: affected package and version, reproduction steps, and impact. Expect an
initial response within a few days. Prompton is a small project — please allow reasonable time for a
fix before public disclosure.

## Supported versions

Only the latest published release of each `@prompton-dev/*` package receives security fixes.
Prompton is pre-1.0; there are no backports to earlier minor versions.

## Scope

In scope: the published packages and the scaffold they generate — the `DocsAgent` Durable Object,
the reindex endpoint, the indexer, and the Starlight plugin.

Out of scope: vulnerabilities in Cloudflare Workers, Workers AI, Vectorize, KV, Astro, or Starlight
themselves (report those upstream), and findings that depend on an operator ignoring the
deployment notes below.

## Security model

Prompton is **self-hosted**. It runs in your Cloudflare account, on your data, under your
configuration — so most of the security surface is deployment-side.

**The reindex endpoint is the sensitive one.** `POST /api/prompton/reindex` rewrites the corpus the
agent answers from. It is protected by a constant-time comparison against the
`PROMPTON_REINDEX_SECRET` Worker secret, and refuses all requests with `503` when that secret is
unset. Optionally, set `PROMPTON_REINDEX_ALLOW_ACCESS=1` and put the path behind Cloudflare Access
to authorize by identity instead. Anyone who can reindex can control what the agent tells your
readers.

**Keep `.dev.vars` out of version control.** It holds local secrets. Scaffolds generated by
`create-prompton` ship a `.gitignore` that excludes it — do not remove that entry, and never commit
the file.

**Rate limits are best-effort.** The KV fixed-window counters on chat and reindex are advisory
under concurrency: they smooth accidental floods, not a determined attacker. Front the Worker with
Cloudflare WAF or Rate Limiting rules if you need enforcement.

**Chat answers are model output.** The agent is instructed to answer only from retrieved excerpts,
but retrieved content is your own documentation — anyone who can write to your docs can influence
what the agent says. Treat the index as trusted input and control who can write to it.

**Chat sessions are unauthenticated by default.** A session is a Durable Object addressed by a
`prompton_sid` cookie, with no identity behind it. Conversation history lives in that Durable
Object; anyone with the cookie value can resume that conversation. Put the site behind Access if
your docs are not public.
